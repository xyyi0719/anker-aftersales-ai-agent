## 一、真实投诉案例（黑猫投诉，情绪类/复杂类测试用例）

| # | 用户原话（摘录） | 型号 | 复合诉求拆解 | 场景类型 |
|---|---|---|---|---|
| C1 | 「90 天内充不进电，客服让我寄回去，说没这个型号了，直接给我寄了个一万毫安的，强盗强买强卖」 | A1681 | 故障报修 + 对处理结果不满（要同型号换新）+ 强烈情绪 | 刁难/情绪 |
| C2 | 「召回退回来的充电宝充不进电，才返回 2 个月，售后不给退回地址，客服就是不回复」 | A1637 | 故障报修 + 召回相关咨询 + 投诉客服响应 | 混淆/情绪 |
| C3 | 「45W 充电器标 45 瓦实际只有 7–10 瓦，充 20 分钟接口焦黑有异味，实测 51.6℃」 | 45W 充电器 | 功率虚标投诉 + 安全隐患（发热焦黑）→ 应触发立即停用+升级 | 刁难/安全 |

**C3 是金子**：涉及发热焦黑异味——安全问题必须最高优先级立即升级，这是最能考验「接稳+幻觉」的用例。

## 二、高频口语说法 → 标准故障类型映射（few-shot 直接可用）

### 充电宝类

| 用户口语 | 标准故障类型 | 对应 FAQ |
|---|---|---|
| 「充不进电了」「充不上电」「插着没反应」 | charge_failure（本体无法充电） | F1 |
| 「充不进去电，灯都不亮」 | charge_failure + 指示灯异常 | F1/F3 |
| 「给手机充不了」「输出没反应」 | output_failure | F2 |
| 「死机了」「屏幕黑了」「自己关机」 | abnormal_behavior（先试复位） | F3 |
| 「烫手」「又烫又慢」「发热严重」 | overheating（**含异味/焦黑→安全升级**） | F4 |
| 「掉电飞快」「24000 毫安虚标」「不耐用」 | drain_fast（先讲 60% 转化率） | F5/F6 |
| 「放着不用就没电了」 | idle_drain（查涓流线/自动关屏） | F6 |
| 「充到 80% 就停了」 | ios_80_limit（非故障，引导关优化充电） | F7 |
| 「显示 0.1W 是不是漏电」 | trickle_display（非故障） | F8 |
| 「屏幕跳 UVP」「充笔记本报警」 | uvp_warning（换 C2 口） | F9 |
| 「跑不满 140W」「功率虚标」 | wattage_mismatch（查线材+设备） | F10/F12 |
| 「插第二个设备就断一下」 | pdo_renegotiation（正常现象） | F11 |
| 「你们这个型号是不是召回的那批」「会不会爆炸」 | recall_inquiry（**强制检索，禁止直接回答**） | 防线用例 |

### 耳机类

| 用户口语 | 标准故障类型 | 对应 FAQ |
|---|---|---|
| 「左边没声了」「一个响一个不响」 | one_side_silent | S1/S2 |
| 「连不上蓝牙」「搜不到耳机」 | pairing_failure | S3 |
| 「老断连」「听一会就断」 | connection_drop | S3 |
| 「连上了但没声音」 | paired_no_sound | S4 |
| 「两边声音不一样大」 | volume_imbalance | S5 |
| 「续航崩了」「听一小时就没电」 | battery_drain（先入盒满充 1 小时再测） | S2 |

### 通用/边界类

| 用户口语 | 标准类型 | 预期行为 |
|---|---|---|
| 「我要退货」「不想要了」 | return_request → 查路由表（30 天/三包 7 日） | 政策路由 |
| 「保修多久」「在保吗」 | warranty_inquiry → 调保修 API | 工具调用 |
| 「我要投诉」「找你们领导」「12315 见」 | complaint_risk（情绪三级） | 立即升级+摘要 |
| 「@#￥%……」（纯辱骂无诉求） | abuse | 安抚一次→询问诉求→仍无诉求则礼貌结束 |
| 「我充电宝和耳机都有问题」 | multi_intent | 拆两个任务 |
| 「我在亚马逊买的，能找你们退吗」 | channel_routing | 亚马逊→平台退，保修→Anker |

**语料规模**：真实投诉 3 条 + 映射 25 条 = 28 条种子；队内各自再用大白话扩写 10 条变体即可破 40。

## 三、注意：2025 召回事件的处理口径

安克 2025 年确有真实召回（供应商电芯原材料变更导致隔膜失效风险，涉及部分批次）。**这意味着 Demo 里「问召回」的用例必须小心**：
- 知识库里应放入**真实召回公告涉及的型号清单**（公开信息）；
- 测试用例选「**不在召回清单内的型号**」提问 → Agent 回答「该型号未在召回列表中，如您有安全疑虑我可为您升级专员确认」——既展示检索命中，又展示边界话术；
- **绝不能让 Agent 对召回问题自由发挥**，这条用例就是 forced_retrieve 动作的存在意义。
