## 数据流

### 1. 文本消息路径
```
用户输入 → 意图分类(3.1) → 情绪识别(4.5)
   ↓
状态机根据意图驱动(3.2)
   ↓
需要工具? → 是 → 工具调用(3.3)
                  ├─ 查订单(2.2)
                  ├─ 查保修(2.2)
                  └─ 检索知识(2.1)
   ↓
低置信度?(4.3) → 是 → 升级话术
   ↓
情绪三级?(4.5) → 是 → 转人工 + 摘要(3.4)
   ↓
最终回答（带出处锁4.2）
```

### 2. 图片消息路径
```
图片输入 → 视觉跳级节点(4.6)
   ↓
四元组 JSON：{型号, 位置, 现象, 置信度}
   ↓
置信度 ≥ 0.8? 
   ├─ 是 + 无冲突 → 跳级到对应排障分支
   ├─ 是 + 有冲突 → 追问澄清
   └─ 否 → 仅作为辅助参考，正常排障流程
   ↓
型号识别为"非安克产品"? → 拒答 + 转人工
```

### 3. 工具调用失败路径
```
工具调用 → 失败
   ↓
重试 1 次 → 失败
   ↓
重试 2 次 → 失败
   ↓
转话术节点（不要让对话死）
   ↓
3 次连续失败 → 升级转人工
```

## 关键节点清单

| 节点 | 块 | 输入 | 输出 | 依赖 |

## 外部接口

### Dify Chatflow 工具配置（块2.2 对接）

三个工具：
- `query_order` → POST /api/orders/{order_id}
- `check_warranty` → POST /api/warranty/check  
- `create_ticket` → POST /api/tickets

详见 `mock_apis/openapi_spec.json`

### 前端 ↔ Dify 接口

- `POST /v1/chat-messages`
- 五字段：`{query, user, conversation_id, inputs, response_mode}`
- 自定义参数放 `inputs`：`{order_id, product_model, emotion_level, ...}`
- 流式事件：`agent_message` / `agent_thought` / `tool_call`
