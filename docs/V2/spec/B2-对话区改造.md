# B2 · 对话区改造

## 目标

1. **用户气泡下方**加情绪与理解辅助气泡——展示系统听懂了什么
2. **输入框上方**加「快速模拟对话」小气泡——点一下就等于替用户回一句，不用打字
3. AI 回复本身追求专业与真人感，**不加**任何辅助信息

### 用户辅助气泡（只给用户消息）

展示两行，最多三行：

```
⚡ 情绪：明显愤怒（L2）
🎯 理解为：故障报修 · Anker 737 · 充不进电
```

- 情绪：由 `state.emotion` 映射中文档位（`L0` 平静 / `L1` 不满 / `L2` 明显愤怒 / `L3` 投诉风险）
- 理解为：`intents` 映射中文 + `product` + 从用户原话里取的关键信息
- **未识别到的项不显示该行**，不显示 `unknown`
- **绝对不加在 AI 气泡下**

### 快速模拟对话（输入框上方）

- 位置：**输入框上方**，标签「快速模拟对话」；AI 气泡下方不再挂选项
- 数据源：`state.options`（本轮服务返回的追问选项）
- 点击 → 发送该选项的 `value`（走现有 `chat.send`，与打字同一条链路）
- 最多 3 个；`options` 为空、或正在推理时不渲染
- **气泡要小**：容器 padding `5px 10px`、气泡字号 `11px`、圆角收小，不抢正文
- **消歧追问也走这里**：不额外做卡片，气泡内容就是用户要回的那几个字（如「扫地机器人」「吸奶器」）

## 验收指标与标准

**命令**

```bash
npm run build && node browser-check.mjs
```

**必须新增的断言**

| 项 | 标准 |
|---|---|
| 用户气泡有辅助信息 | 用户消息下方出现情绪文案；AI 消息下方**不出现** |
| 情绪档位正确 | 注入 `emotion='L2'` → 显示「明显愤怒」 |
| 理解为三要素 | 注入意图/产品/关键信息 → 三者在同一行以 `·` 分隔 |
| 未识别不显示 | `emotion='L0'` 且无其它信息时，不出现 `unknown` 字样 |
| 芯片可点 | 注入 2 项 options → 出现 2 个芯片 |
| 位置正确 | 「快速模拟对话」出现在输入框上方（`bottom <= textarea.top`） |
| 点击即发送 | 点第一个芯片 → 发出的请求 `query` 等于其 `value` |
| 空选项不渲染 | `options=[]` → 芯片容器不存在 |
| 上限 | 注入 4 项 → 只渲染 3 个 |
| 脚本注入防御 | 芯片与辅助气泡的文本经转义，注入 `<img onerror>` 不执行 |
| 消歧不用卡片 | 走离线兜底发「我的s1pro不吸了」→ 出现「扫地机器人 / 吸奶器」气泡，且页面无消歧卡片 |
| 排障可推进 | 点「换了也不行」→ 出现下一问「屏幕有反应吗」，气泡更新为「屏幕黑屏」 |

## 边界

- AI 气泡**不许**加情绪/理解辅助信息（追求真人感）。
- 不许在前端从用户原话里"猜"情绪或意图——只渲染模型给的值。缺就当没有。
- 气泡只是快捷方式，**自由打字必须依然可用**，不许做成唯一入口。
- **不许用大块卡片承载追问**（消歧已由卡片改为小气泡）。
- 不许动 `MessageBubble` 里既有的出处展示逻辑（B1 接管）。
