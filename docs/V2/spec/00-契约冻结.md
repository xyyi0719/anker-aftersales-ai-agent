# 00 · 契约冻结

> **这是双方唯一的接口真源。** 改它要走 `README.md` §4 的变更流程。
> 配套工具：`scripts/check_contract.py`（三端字段一致性检查，不一致就失败）。

---

## 0. 一轮对话的数据流

```
用户文字+图片
  → Dify start
  → Dify LLM「extract」        产出 extraction JSON        ← 契约 A 产出
  → Dify code「pack」          包成 HTTP body
  → Mock POST /api/chat/turn                                ← 契约 A 消费
  → Mock 产出 answer + state                                ← 契约 B 产出
  → Dify LLM「compose」        把 answer 改写成用户可见措辞   ← 表达层，不改事实
  → Dify code「unpack」        校验越界 + 把 state 编进证据标记
  → Dify assigner「save」      写回 conversation.session_state
  → Dify answer                输出
  → 前端 parseEvidence 解出 state                            ← 契约 B 消费
  → 前端渲染                                                 ← 契约 C
```

## 契约 A · extraction（Dify extract 节点产出，Mock 消费）

| 字段 | 取值域 | 消费点 |
|---|---|---|
| `intents` | 数组：`troubleshooting` \| `inquiry` \| `return_or_exchange` \| `transfer_human` \| `complaint` \| `out_of_scope` | `engine.py` 判断是否进排障 |
| `emotion` | `L0` \| `L1` \| `L2` \| `L3` | 情绪与升级判定（**模型负责，代码正则仅兜底**） |
| `branch_answer` | 排障节点选项的原文字符串；未回答/不确定时为**空字符串** | 故障树推进 |
| `summary` | **新增**。一句话会话摘要，≤40 字 | 透传到契约 B |
| `vision` | 见下；**无图片时必须是 `{}`** | 视觉分流 |

### `vision` 字段

| 字段 | 取值域 |
|---|---|
| `brand` | 品牌名或 `unknown` |
| `product_model` | `Anker737` \| `Soundcore` \| `unknown` |
| `fault_location` | 中文部位描述或 `unknown` |
| `fault_phenomenon` | `鼓包` `冒烟` `起火` `漏液` `焦黑` `异味` `接口损坏` `内部暴露` `线材破损` `线材烧损` `外壳破损` `屏幕异常` `正常` `unknown` |
| `confidence` | `0.0`–`1.0` |
| `is_anker_product` | `true`（默认，含看不清时）\| `false`（**仅在确证竞品时**） |
| `evidence` | 一句话视觉依据 |

### 契约 A 硬规则

1. 安全类现象（`鼓包` `冒烟` `起火` `漏液` `焦黑` `异味`）**不受置信度门槛限制**，命中即熔断。
2. `is_anker_product === false` 时**不得进入排障流程**。
3. 图片结论与用户文字冲突时**不跳级**，追问确认。
4. **不得从静态图片判断**是否试过换线、是否在保、是否人为损坏。

前端门禁：`schema_version === 1 && mock === true`，否则整段丢弃。

### 内部会话字段（随 `state` 下发，但前端不渲染）

这些字段由 `engine.py` 维护、随证据标记一起下发，前端**不读取**。列在这里是为了满足
「三端代码里出现的每个字段都能在契约里找到定义」——由 `check_contract.py` 强制校验。

| 字段 | 类型 | 含义 |
|---|---|---|
| `last_query` | string | 上一轮用户原话，供规则服务自己比对 |
| `order_id` | string | 已识别的订单号 |
| `awaiting_product` | bool | 正在等待用户澄清产品品类（S1 Pro 消歧） |
| `pending_policy` | string | 用户提出政策诉求但缺订单号，暂存待补 |
| `angry_streak` | int | 连续 L2 情绪的轮数 |
| `asked_node` | string\|`null` | 上一轮已经问过的节点，用于判断是否在重复追问 |

### `options[]` 定义

```json
[ { "label": "充电宝自己充不进", "value": "自己" } ]
```

- **位置**：放在 `state` 内，随现有证据标记下发。**不加顶层字段、不加新标记。**
- **产出规则**：**只有排障追问节点产出 `options`**；其余情况为空数组 `[]`。
- `label` 说人话（用户视角），`value` 是故障树的选项键，**点击时发送 `value`**。
- 每轮最多 **3** 个。
- 选项键 → 显示文案的映射表见 `A1-规则服务输出.md`。

### 契约 B 硬规则

1. 无图时 `vision` 必须是 `{}`，不得留上一轮残留。
2. `options` 缺失或空数组时，前端不得自行编造选项。
3. 所有面向用户的数值必须来自真实计算，**不得写死**。

## 契约 C · 前端渲染依赖

| 前端字段 | 取值来源 |
|---|---|
| 会话摘要 | `state.summary` |
| 诉求标签 | `state.tasks` 按 `kind` 映射颜色 |
| 用户档案 | 由 `state` 中的订单信息 + `users.json` 聚合 |
| 产品信息 | `state.vision` + `state.product` |
| 处理依据 | `state.citations` |
| 工单流程 | `state.ticket` + `history` |
| 情绪辅助气泡 | `state.emotion` + `intents` + `product` |
| 选项芯片 | `state.options` |

### 取值纪律

1. **统一阈值 0.8**（视觉跳级门槛）。界面文案不得出现 0.7、0.72、0.75 等其它数字。
2. `unknown` 一律显示为「未识别」，不留英文。
3. 缺失字段显示占位（「待提取」「未识别」），**不得编造数值或型号**。
4. 现象词表、安全类判定，三端必须与契约 A 完全一致。
