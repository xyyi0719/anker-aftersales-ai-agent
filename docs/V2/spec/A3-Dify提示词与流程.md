# A3 · Dify 提示词与流程

## 目标

1. 让提取节点顺带产出会话摘要
2. 让表达层做到「先回应用户，再往下推进」，而不是念流程
3. YAML 一律由脚本从 `chatflow/prompts/` 生成，**不手改、不在此阶段导入 Dify**

## 输入依赖

- `00-契约冻结.md`（`summary` 字段定义）

## 产出物

| 文件 | 改动 |
|---|---|
| `chatflow/prompts/08-extract-vision.txt` | 输出 JSON 增加 `summary` 字段与产出规则 |
| `chatflow/prompts/09-compose-answer.txt` | 增加「先回应再推进」硬规则 |
| `scripts/build_dify.py` | 无需新增节点；确认提示词从 `prompts/` 读取 |
| `chatflow/anker-aftersales-chatflow.yml` | 重新生成（8 节点） |

### `summary` 产出规则（写进 08）

- 一句话，≤40 字，说清「在排查什么问题 + 已确认什么 + 当前卡在哪」
- **不确定就留空字符串**，不要编造
- 只描述已发生的事，不含建议、不含结论

### 「先回应再推进」写进 09

在现有铁律后追加：

1. **第一条必须是回应用户刚说的内容**，确认关键信息，再进入下一步
   - ✅「充不进电的话，我们先定位一下是哪种情况——」
   - ❌ 直接抛问题
2. 追问时用半句话说明**为什么问**，让用户知道答了有什么用
3. 不出现机制名、防线编号、"系统已触发"这类播报

### 表达层输入形态（可选增强，建议一并做）

现状：表达层拿到的是规则服务产出的**成句模板**，只做改写，很难真的自然。
建议：让规则服务同时给一份**结构化事实**（`state` 里已有），提示词改为「以 `state` 的事实为准，`answer` 作为必须保留的关键信息清单」，让模型自己组织语言。

> 这条会同时动 A1 与 A3，**如果决定做，要在 `00-契约冻结.md` 里登记**。

## 验收指标与标准

**命令**

```bash
python -m pytest tests/test_dify.py -q
```

**必须通过的断言**

| 项 | 标准 |
|---|---|
| 节点结构 | `['start','extract','pack','service','compose','unpack','save','answer']`，顺序不可变 |
| 连通性 | 每条边的 `source`/`target` 都存在于节点集合 |
| compose 不参与判定 | `compose` 类型为 `llm`，`vision.enabled === false` |
| 提示词来自文件 | 生成后的 YAML 里，extract 与 compose 的提示词与 `chatflow/prompts/` 下文件内容一致 |
| 无网络调用 | 所有 `code` 节点不含 `urllib`/`requests` |
| `summary` 在契约里 | extract 提示词包含 `summary` 字样与产出规则 |
| 「先回应」在提示词里 | compose 提示词包含「先回应」相关约束 |

## 边界

- **本阶段不导入 Dify**。YAML 重新生成后放在仓库里，导入由人工在合并审核后执行。
- 不许手改生成的 YAML（改了下次生成就丢）。
- 不许改动故障树逻辑（那是 A1 的事）。
- 不许在表达层引入新的判定（它只能改写，不能决定流程或权益）。
