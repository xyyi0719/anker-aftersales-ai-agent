### 四道防线的表现：状态词 + 点亮上抬（不再写小字）

- **文案**：未触发显示状态词（「正常」/「已推进」/「已升级」/「已阻断」）。**卡片内不再写小字解释** —— 原来的原因行（「已按流程推进 N 步」「已引用 N 条」「无可靠依据，已升级」「已阻断越权请求」）与机制说明全部去掉。
- **动作**：走到某一关时，对应卡片**微微亮起并上抬**（`transform: translateY(-4px)` + 各自强调色描边/柔光 + 背景淡染），刚触发时另有一次光晕脉冲。
  - 强调色：流程锁 `#8b5cf6`｜出处锁 `#0084ff`｜置信度锁 `#f59e0b`｜权限锁 `#38bdf8`
- 汇总行：未触发「全部正常」，触发时「第 N 道已触发」。

## 验收指标与标准

**命令**

```bash
npm run build
node browser-check.mjs
grep -rn "<上面每条>" frontend/src/   # 应无输出
```

| 项 | 标准 |
|---|---|
| 清理彻底 | 清理清单里每一条在 `frontend/src/` 的出现次数为 **0** |
| 状态词到位 | 四道防线未触发时，每格只显示状态词，不显示参数说明或原因小字 |
| 点亮与上抬 | 触发某一道后，该卡片带 `is-active`，且 `transform` 非单位矩阵（视觉上浮） |
| 无死 CSS | `grep -c benchmark styles.css` 为 0 |
| 无新增解释文字 | 不引入新的自述式文案 |
| 移动端 | 375px 下无横向溢出 |
| 桌面端 | 1440px 下布局不破 |
| TS 干净 | `npm run build` 无 error 无 warning |

## 边界

- **不许改文案的事实内容**（如把「待专员接单」改成「已接单」）。
- 不许为了让 grep 通过而把文案挪成变量拼接（那是绕过检查）。
- 不许动 `mock_apis/`、`chatflow/`。
- 不许删与 benchmark 无关的 CSS。
