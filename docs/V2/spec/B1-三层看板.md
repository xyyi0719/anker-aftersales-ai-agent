### 三层结构

**上层 · 会话摘要 + 诉求**
- 摘要：`state.summary` 一句话原样展示
- 诉求标签：由 `state.tasks` 的 `kind` 映射，**按类型着色**

| kind | 颜色 |
|---|---|
| 排障 `troubleshooting` | `#38bdf8` |
| 核保 `warranty` | `#06b6d4` |
| 退货 `return` | `#f59e0b` |
| 投诉 `emotion` | `#ef4444` |
| 安全 `safety` | `#dc2626` |
| 咨询 `faq` | `#94a3b8` |

**中层 · 用户档案 + 产品信息 + 处理依据**
- 用户档案：姓名/等级、订单号、渠道、区域、保修状态（A2 的数据）
- 产品信息：型号、品类、故障部位、故障现象、置信度、安全状态
- 处理依据：`state.citations`，每条带 `chunk_id` + 文本 + 官方来源链接

**下层 · 工单流程** → 见 `B3-工单流程与转派.md`

### 视觉层级（关键，否则等于把 tab 换成堆叠）

- 上层摘要**字号最大**，是第一眼落点
- 中层左右分栏（档案 / 产品），处理依据弱化成小字列表
- 下层可折叠，默认展开

## 验收指标与标准

**命令**

```bash
npm run build          # 无 TS 报错
node browser-check.mjs # 全绿
```

**必须通过的断言**

| 项 | 标准 |
|---|---|
| 三层存在 | 页面上能定位到上/中/下三层的容器 |
| 摘要渲染 | 注入 `summary` 后出现在上层；为空时显示占位，不显示 `undefined` |
| 诉求着色 | 注入含 `safety` 与 `troubleshooting` 的 tasks，两个标签颜色不同 |
| 字段来源唯一 | 组件里不出现 `state.visionEvidence ?? {写死对象}` 这类兜底（旧代码的伪造模式） |
| 缺数据显示占位 | `vision` 为 `{}` 时，产品信息显示「待提取」，**不出现任何数字** |
| 无硬编码数值 | 全组件不含 `0.88`/`0.75` 之类写死的置信度 |
| 旧 tab 已移除 | 页面上不再出现 `决策与路由`/`看图跳级`/`情绪监测`/`出处检索` 四个 tab 标签 |

## 边界

- **不许改 `mock_apis/`、`chatflow/`**。
- 不许在前端推断或补全后端没给的字段（旧代码的伪造模式，已因此返工过一次）。
- 不许出现新的解释性标题（如「L3 可解释性…」），三层结构自带语义。
- 不许引入新的第三方 UI 依赖。
