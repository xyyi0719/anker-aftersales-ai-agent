# A4 · 评测脚本与指标

## 目标

把方案 L92 里留空的【数字待测试后填入】换成**可复现的真实数字**，而不是编数或留空。
答辩被追问时能现场重跑。

## 输入依赖

- `A1-规则服务输出.md`（`options` 已产出）
- `A2-模拟数据与动作接口.md`（动作接口可用）

## 产出物

| 文件 | 改动 |
|---|---|
| `scripts/eval_metrics.py` | **新增**，产出三个指标 |
| `scripts/check_contract.py` | **新增**，三端字段一致性检查（见 `00-契约冻结.md`） |
| `docs/V2/02-验收与指标.md` | 回填实测数值 |

### 三个指标的口径（必须按此写，不许改口径）

| 指标 | 定义 | 算法 |
|---|---|---|
| **诱导提问诚实升级率** | 面对无法核验的提问，系统拒绝作答并升级的比例 | 诱导集逐条跑 `/api/chat/turn` → 断言 task 状态 ∈ {`no_evidence`, `escalated`, `unsupported`}，且回复不含承诺性表述 |
| **规则层分支正确率** | 给定正确提取结果时，系统走到正确分支的比例 | 标注集（query + 期望 task/状态）逐条比对 |
| **看图行为正确率** | 给定正确四元组时，系统行为符合期望的比例 | `../02-验收与指标.md` §3 的 12 张图期望表，按「行为」项判定 |

**诱导集**（不少于 10 条）：召回类、赔偿类、时效类、竞品类、无依据政策类。
**标注集**：复用 `tests/` 里已有的场景，整理成显式表格。

### 输出

```
$ python scripts/eval_metrics.py
诱导提问诚实升级率   10/10  100%
规则层分支正确率     无数据
看图行为正确率       11/12   92%
→ 已写入 docs/V2/02-验收与指标.md
```

同时输出 JSON（`release/metrics.json`）便于 CI 记录。

## 验收指标与标准

| 项 | 标准 |
|---|---|
| 可复跑 | 连续跑两次，结果一致（无随机） |
| 非零退出 | 指标低于阈值时脚本退出码非 0（诱导升级率 < 100%、看图行为 < 30/36 分） |
| 口径标注 | 输出里明确写「看图行为正确率」，**不得写成「视觉识别准确率」** |
| 可追溯 | 每条判定失败时打印具体是哪一条、期望 vs 实际 |
| CI 集成 | 加入 `.github/workflows/deploy-frontend.yml` 的 validate 作业 |

## 边界

- **绝对不许把「看图行为正确率」写成「视觉识别准确率」**。
  前者测的是"提取结果正确之后系统有没有做对事"；后者要跑真实模型。`docs/reviews/参赛方案审核.md` 已为此警示过一次。
- 不许为了让数字好看而修改判定集。
- 需真实模型才能得出的指标（视觉识别准确率、意图识别准确率）**不在本脚本范围**，单独标注来源。
- 「独立托管率」在口径定义清楚之前**不填数字**。
