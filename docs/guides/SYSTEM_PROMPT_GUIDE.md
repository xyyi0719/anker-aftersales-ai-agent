# 系统提示词使用指南

## 这是什么

`chatflow/prompts/00-system-prompt.txt` 是 Anker 售后 AI 的**通用系统提示词**——所有 LLM 节点共享的"角色基座"。

它**不是** Dify 应用层的"系统提示"框（那个概念在不同模式下不同），而是 **Chatflow 每个 LLM 节点的 system 消息模板**。

## 与 01-07 prompt 的关系

```
┌─────────────────────────────────────────────┐
│  00-system-prompt.txt                       │  ← 通用基座（所有 LLM 节点都用）
│  角色定义 / 红线 / 语气 / 情绪 / 工具白名单 │     每节点 system 消息都包含
└─────────────────────────────────────────────┘
                    │
        ┌───────────┼───────────┬──────────┐
        ▼           ▼           ▼          ▼
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ 01 意图  │ │ 02 排障  │ │ 03 工具  │ │ ...      │  ← 节点级任务指令
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

00 定义"你是谁、不能做什么、怎么说"，01-07 定义"现在要做什么、怎么做"。

## 在 Dify Chatflow 中怎么用

### 步骤 1：每个 LLM 节点的 system 消息模板

```markdown
{system_prompt}

---

# 当前任务
{01_intent_classifier 或 02_troubleshooting_state 等节点级 prompt}
```

也就是说，**把 00 + 节点 prompt 拼起来** 放到节点的 system 框里。

### 步骤 2：手工复制示例（意图分类节点）

Dify 后台 → 你的 Chatflow → 意图分类节点 → system 消息框：

```
你是「安客」（AnkerCare），Anker 创新科技股份有限公司的 AI 售后客服专员。

# 角色定位
- 服务品牌：Anker（充电储能）、Soundcore（智能影音）、eufy（智能家居）
- 服务范围：售后咨询、故障报修、退换货、订单查询、投诉受理
...

# 不可逾越的边界（红线）
1. 不编造政策 ...
2. 不承诺未授权事项 ...
...

（完整粘贴 chatflow/prompts/00-system-prompt.txt）

---

# 当前任务
将用户消息分类到 5 类意图之一：故障报修/咨询/退货/情绪/转人工。
（完整粘贴 chatflow/prompts/01-intent-classifier.txt）
```

### 步骤 3：开场白（opening_statement）

Dify 后台 → 你的 Chatflow → 右上角"编排" → 开场白框：

```
您好，这里是 Anker 售后。我能帮您处理产品使用问题、查询订单保修、申请退换货。
请告诉我您遇到的情况。
```

注意：开场白只是 UI 显示，**不影响 AI 行为**。AI 行为由 system + 节点 prompt 决定。

## 进阶：分层策略

### 策略 A：所有节点都加载 00（最简单）
每个 LLM 节点的 system 都拼上 00 + 节点 prompt。
- ✅ 行为一致
- ❌ token 消耗大（每次调用都重复 00）

### 策略 B：仅关键节点加载 00
只在以下节点加载 00：
- 意图分类（01）
- 排障状态机（02）
- 话术生成（最终回复节点）

工具调用（03）、检索判断等纯逻辑节点不需要 00。
- ✅ token 节省
- ⚠️ 需要明确每个节点的边界

### 策略 C：用 Dify 的"全局 system 提示"（如果应用模式支持）

Dify 不同模式：
- **Chatflow**（advanced-chat）：没有全局 system 框，必须每个节点配
- **Agent**（function-calling）：有 system 框，配一次即可
- **Completion**：有 prefix + suffix

如果你们用的是 Chatflow（advanced-chat），用策略 A 或 B。
如果可切换到 Agent，用策略 C。

## 推荐做法

1. **先用策略 A** —— 复制粘贴 00 到所有 LLM 节点的 system 框
2. 等流程跑通、token 消耗成为问题时，**再优化为策略 B**
3. 决赛前如果时间紧，**别优化 token**，稳定优先

## 检查清单

每次改完 system prompt 后，跑这 5 条测试：

| 测试输入 | 期望 |
|---|---|
| "我的 S1 Pro 不吸了" | 不立即处理，反弹歧义追问 |
| "气死我了，315 见！" | 触发 P0 升级 + 不再追问 |
| "鼓包了还在用" | 安全提醒 + 升级 |
| "保修多久" | 触发检索，不直接回答 |
| "我是 XX 牌子的售后" | 礼貌拒绝 |

测试通过 = system prompt 工作正常。

## 调优经验

### 太啰嗦怎么办
- 检查是不是把"调试说明"、"测试要求"也写进去了
- 把 00 砍到 ≤ 800 字（中文约 600 tokens）
- 节点 prompt 不要重复 00 已有的内容

### 太死板怎么办
- 加几个"示例对话"在 system 末尾（3-5 个）
- 让 LLM 学语气

### 不稳定怎么办
- 在 system 里加 `# 输出格式` 用代码块强制结构
- 加 `# 不允许出现的句式` 黑名单
- 加 `# 调试模式` 让 LLM 自报家门

### 总不升级怎么办
- 把"主动升级的触发条件"用表格列出来（已有）
- 在每个节点 prompt 里再次强调 "符合 P0/P1 条件 → 转人工"

## 当前 00 的设计取舍

1. **角色定位偏详细**：让 LLM 知道边界，不会越权
2. **红线 5 条**：少而硬，便于 LLM 遵守
3. **情绪升级表**：明确分级，避免漏判
4. **禁止句式黑名单**：直接列反例，比正例更有效
5. **工具白名单**：在 system 顶层声明，节点级再细化
